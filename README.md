# Ghost Data Still Exists: a deletion-audit agent

My submission to **HackerRank Orchestrate (October 2026)**, my first hackathon. I finished at rank **375 of 4,090** (top 10%).

When a company says "your data has been deleted", is it really gone? For each of 518 deletion requests, this agent works through six steps:

1. Decides whether the person actually asked for deletion, in any language.
2. Rebuilds every identifier they ever had: current and old emails, sha256 email hashes, phone numbers.
3. Searches databases, replicas, logs, exports, analytics, backups, screenshots and PDFs for their data.
4. Works out the true state of every copy at the audit time. Workflow statuses are treated as claims, not proof.
5. Applies the company's deletion policy: delete, redact, anonymize, retain, or keep an account tombstone.
6. Writes an ordered plan for each request. The plan covers findings, then remediation, then verification.

## Architecture

```
request   ─► intent.py    rules → Claude Haiku 5.5 second opinion → Claude Sonnet 5.5 tie-break
identity  ─► data.py      current + historical emails, sha256 hashes, phones (exact matching)
evidence  ─► extract.py   JSON / TXT / 5 log formats / SQLite snapshots → normalized facts
            vision.py     screenshots + PDFs read by Claude Sonnet 5.5 into a strict JSON schema
per case  ─► audit.py     link facts to the person, keep evidence ≤ audit_at, latest copy wins
            state.py      present / absent / PII exposed / flow enabled / restore allowed
            policy.py     deletion_rules.csv → findings, remediation, verification
            verify.py     output-contract validator · llm.py: schema checks, retry, cache, fallback
```

The design choice I'd revisit is the split of work. Here, code makes almost every decision and Claude only reads language and images. I'd now let the LLM reason over the policy and evidence, and make the hard-coded rules validators of its output. The [write-up](docs/article.md#where-i-could-have-done-better) explains why.

## Run it

The challenge data isn't included in this repo. Get it from the official starter repo:

```bash
git clone https://github.com/interviewstreet/hackerrank-orchestrate-october26.git /tmp/orchestrate
cp -R /tmp/orchestrate/dataset ./dataset
```

Then:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r code/requirements.txt
export ANTHROPIC_API_KEY=...            # or put it in an uncommitted .env
python3 code/main.py                    # → output.csv, output_v0_rules.csv, review_queue.csv
python3 code/main.py --rules-only       # deterministic baseline, no API calls
python3 code/evaluation/eval.py         # score the 32 samples and list every miss
python3 code/evaluation/unit_property_tests.py
python3 code/evaluation/validator_tests.py
python3 code/evaluation/custom_cases.py
```

- **Requirements:** Python 3.10+.
- **Cost:** a full live run takes about a minute and costs about $0.30.
- **Caching:** Claude replies are cached in `code/cache/` (git-ignored), so later runs are free and give identical output.
- **Submitted output:** [`results/output.csv`](results/output.csv). Flagged cases are in [`results/review_queue.csv`](results/review_queue.csv).

The dataset is fictional and was generated by the organisers. No real personal data is used here.
